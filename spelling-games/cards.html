🎲 Spelling Games — Learner Cards

Print, cut out and hand one card to each child. They scan their code (or open their page and type it) to see everything they can play this week.

QR codes are generated in your browser using the qrcode-generator library (MIT licence, vendored locally in vendor/qrcode.js, no external service or network call). Learners come from the school's Bromcom roster automatically (see admin/index.html's "Sync roster" — nobody needs to type names in anywhere) and the current week comes from the shared TermDates calendar. roster.js is only the offline fallback used if the backend is unreachable. Each card's QR code goes to play/index.html — a learner's own page listing every game available for their year and the current week — rather than one QR per game, so a new game never means reprinting cards. Add a new game to that list by adding one entry to GAMES in roster.js.

"🏷️ Download labels" makes a PDF of the same code + PIN + QR code, laid out for a 99×42mm label sheet (Avery L7159, 12 per A4 sheet) instead of full cut-out cards — the identity part of the card that doesn't change from week to week, so it only needs printing once. PDF generation uses jsPDF (MIT licence, vendored locally in vendor/jspdf.umd.min.js). The label geometry (exact sizes and per-row/column nudges) is copied from this school's own drawer-peg-labels tool, which already calibrated it against a real printed sheet — re-check a test sheet if labels ever drift, rather than trusting the numbers blindly on a different printer.
